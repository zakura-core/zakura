## Changed

- **Breaking for v2 P2P:** a node's ID is now the hash of a list of tagged
  keys instead of its Ed25519 public key, so every node's ID changes once.
  The v2 protocol moves to version 4 (ALPN `p2p-v2/4`) with no overlap with
  version 3: nodes that run both stacks keep reaching older releases over
  the legacy protocol, and nodes that run only the v2 stack lose peers on
  older releases until those upgrade. Existing configs need no edits. In
  `zakura.bootstrap_peers` and pinned `network.unconditional_peers` entries a
  bare 64-hex value still names the peer's Ed25519 key, and `id:<hex>` names
  a node ID, which is the form a node now prints for itself at startup
  ([#2659](https://github.com/zakura-core/zakura/pull/2659)).
- Raised `zakura-quic` to 2.0.0. `NodeId` is 32 opaque bytes, so
  `NodeId::key()`, `NodeId::verify_strict()` and the conversion from a
  `NodeKey` are removed, and `NodeAddr` has a new public `key` field
  ([#2659](https://github.com/zakura-core/zakura/pull/2659)).
