## Security

- Preserve native block-sync progress under sustained traffic: GetBlocks
  requests draw on existing storage and output capacity instead of the shared
  message-rate allowance, responses require matching authorization, and the
  specific reader rejection is recorded before connection cleanup can hide it.
  Advertise 16 remotely initiated streams, clamp a peer's advertised stream
  count to the local limit instead of rejecting its hello, and keep 8 MiB
  per-stream and 32 MiB per-connection receive windows so three paused sibling
  streams still leave progress credit while body throughput on delay-only
  links stays within about 1% of the previous windows
  ([#981](https://github.com/zakura-core/zakura/pull/981)).
