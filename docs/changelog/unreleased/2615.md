## Fixed

- With `[network.block_download_score_and_hedge]` enabled, a slow large block no longer makes a
  legacy peer look slow for every request. Pings and verified block replies up to 14,600 bytes
  measure its round trip. Larger verified replies still clear a missed-block mark and teach the
  node how long that peer takes to transfer large blocks.
- When the first reply's header matches the requested block and its declared length fits the
  block limit, the node uses that length to compare the first peer and other announcers. A
  pending second request is reconsidered as soon as the size arrives. The prediction is at
  least one round trip. Block delivery traces include `wire_bytes`, with `expected_ms` and
  `slowdown` on large replies. Second-request traces include `decision_block_bytes` and the
  predicted times for that size ([#2615](https://github.com/zakura-core/zakura/pull/2615)).
