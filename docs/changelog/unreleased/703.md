## Added

- Added historical treestate serving for a verified-commitment-trees fast-synced
  archive node: it answers `z_gettreestate` and the `getblock`/`getblockheader`
  tree sizes for the height band where it stored no per-height note commitment
  tree. The node replays retained block bodies forward from the nearest frontier
  it already holds and serves the result only if it reproduces the authenticated
  root it already stores, so the treestate is verified rather than trusted.
  Mainnet uses its reviewed frontier grid embedded in the binary, so production
  archive nodes enable derivation without deployment-time configuration.
  `state.historical_frontier_artifact` remains an optional override for tests
  and custom deployments. An override that cannot be read still fails at
  startup. A grid that ends below this database's own fast-sync handoff is
  ignored, and the affected historical trees are reported as unavailable. A
  grid whose entries do not tile genesis through `last_checkpoint` at gaps of
  at most `MAX_HISTORICAL_TREE_REPLAY_BLOCKS` (100,000) is still refused, so a
  covering header over a sparse or mid-chain-only artifact cannot start. A
  grid entry that fails its root check is skipped in favor of the next-lower
  cell rather than a genesis replay. The same constant bounds a single
  request, so a grid that loads but whose entries fail their root checks
  cannot fall back to replaying the whole band; grid spacing is what decides
  the cost of a request in normal serving. Pruned mode still cannot serve historical
  treestates, because replay reads block bodies it does not retain
  ([#703](https://github.com/zakura-core/zakura/pull/703),
  [#739](https://github.com/zakura-core/zakura/pull/739)).

## Changed

- The Mainnet release-state export now produces the historical note commitment frontier
  grid alongside the checkpoint list, VCT frontier, and completed-subtree roots.
  `zakura-checkpoints` gained `--mainnet-frontier-grid-output` and its spacing flags, and
  the three artifact outputs became one required set, so a replacement checkpoint list can
  never ship without its coupled release state. The grid is generated for the checkpoint
  that run selects: a node refuses to start when the grid's checkpoint is below its own
  fast-sync handoff, and that handoff comes from the embedded checkpoint list, so the two
  have to advance together. The bundle, its digest verification, the import step, the
  provenance manifest, and the release-state gate all carry the grid, and the import
  requires each update to extend the committed grid rather than rewrite it
  ([#735](https://github.com/zakura-core/zakura/pull/735)).

- Grid generation now reads stored per-height trees wherever a database has them and
  replays retained block bodies only across a fast-synced database's absent band. A legacy
  archive node therefore generates the whole grid without replaying, and coverage extends
  to the release checkpoint instead of stopping at the generating node's own handoff. The
  export is read-only through a RocksDB secondary, so it does not need a stopped node; it
  does need an archive one, because the grid covers heights a pruned database no longer
  holds ([#735](https://github.com/zakura-core/zakura/pull/735)).

## Removed

- Removed `state.derive_historical_trees` and `state.max_historical_tree_replay_blocks`
  before they shipped. Derivation is implied by archive verified-commitment-trees
  fast-sync, or its durable database marker, plus an available grid. The marker keeps an
  existing absent band serviceable after sync settings change. A configuration file
  carrying either removed key no longer parses
  ([#739](https://github.com/zakura-core/zakura/pull/739)).
