## Added

- Mainnet now ships a reviewed historical frontier grid embedded in the binary, so a
  verified-commitment-trees fast-synced archive node serves `z_gettreestate` and the
  `getblock`/`getblockheader` tree sizes across its absent band with no deployment-time
  configuration. Serving previously required pointing
  `state.historical_frontier_artifact` at a grid; that setting remains, now as an override
  for tests and custom networks. The embedded grid carries no trust weight — every entry
  is still checked against the authenticated root this node already stores before it
  anchors anything — but its bytes are bound to the committed provenance manifest, so a
  grid that has fallen out of step with the embedded checkpoint list fails CI rather than
  leaving the band silently unavailable
  ([#703](https://github.com/zakura-core/zakura/pull/703),
  [#739](https://github.com/zakura-core/zakura/pull/739)).

## Changed

- The Mainnet release-state bundle now carries the historical frontier grid alongside the
  checkpoint list, VCT frontier, and completed-subtree roots, and the four are one required
  set, so a replacement checkpoint list can never ship without its coupled release state.
  Bundle fetching requires the grid and verifies its digest, the importer requires each
  update to extend the committed grid rather than rewrite it, and the provenance manifest
  records its digest, size, and entry count. `scripts/check-release-state.sh` binds the
  committed grid bytes to that record and now runs on every pull request, because the grid
  is the one release-state artifact not embedded in the binary and so not covered by the
  existing `embedded_mainnet_final_frontiers_parse` check
  ([#703](https://github.com/zakura-core/zakura/pull/703),
  [#735](https://github.com/zakura-core/zakura/pull/735)).
