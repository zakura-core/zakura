## Added

- Seed the NSM value balance immediately before NU7 with the block subsidy and
  fees that earlier coinbase transactions never claimed, following the
  2026-09-15 ZIP Editor call and zips#1354. Mainnet uses 36,858,445,520 zatoshi
  and Testnet 55,768,414,957, both measured at the last pre-NU6 height. Every
  other network starts at zero, and configured networks can set their own
  ([#1040](https://github.com/zakura-core/zakura/pull/1040)).

## Changed

- Derive the ZIP 234 payout fraction from the halving interval at each height,
  `floor(LN2_SCALED / HalvingInterval(height))`. The fixed 4126 numerator was
  calibrated for 75-second blocks, so ZIP 218's 25-second blocks paid the
  balance out three times too fast
  ([#1040](https://github.com/zakura-core/zakura/pull/1040)).
- Reject a block that makes the NSM value balance negative from NU7 activation,
  not from the later reissuance start height
  ([#1040](https://github.com/zakura-core/zakura/pull/1040)).
- Rename the issuance deficit to the NSM value balance throughout, and rename
  the ZIP 234 start height parameter to the NSM reissuance height. The
  `zip234_start_height` configuration field is now `nsm_reissuance_height`
  ([#1040](https://github.com/zakura-core/zakura/pull/1040)).
