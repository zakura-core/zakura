## Security

- Prevent a peer's modified block body from permanently excluding a valid header
  and its descendants from native block sync. Duplicate padding can preserve the
  transaction Merkle root (CVE-2012-2459), and NU5 authorization changes can preserve
  transaction IDs. Verify the relevant header commitments before using a body
  failure as permanent evidence. Check reconstructed transaction lists through the
  shared consensus rules and their actual parent state without committing them, so
  padding cannot hide committed invalid transactions or bypass side-branch checks.
  Defer the faulty supplier so another peer can deliver the correct body. This
  prevents new incorrect exclusions but does not clear previously stored ones
  ([#999](https://github.com/zakura-core/zakura/pull/999)).
