## Changed

- Block announcements are bounded to the latest work: each peer-to-peer protocol keeps at
  most the latest committed tip and a short queue of this node's own mined blocks waiting
  for a peer, where a committed own block buries every own block below its height, so a
  node that committed blocks with no peers connected announces the current tip and its
  newest own blocks to the first peer instead of a backlog of buried blocks
  ([#1955](https://github.com/zakura-core/zakura/pull/1955)).
- Each peer-to-peer protocol announces at most 16 of this node's own blocks at once; further
  blocks wait for one to finish, while the committed tip is still announced
  ([#1955](https://github.com/zakura-core/zakura/pull/1955)).
- A Zakura peer whose gossip queue is full gets up to 3 seconds to make room for a block
  announcement, as a busy legacy peer does, instead of counting as a failed delivery at once
  ([#1955](https://github.com/zakura-core/zakura/pull/1955)).

## Fixed

- A node with only Zakura peers announces its tip and its own mined block to the first
  peer that connects, and a block announcement to Zakura peers that reached nobody is
  retried instead of being recorded as sent
  ([#1955](https://github.com/zakura-core/zakura/pull/1955)).
- A node that commits two of its own blocks at one height while it has no peer announces
  both to the first peer that connects, instead of only the later one, and a block this
  node submitted that the chain has not committed yet is no longer kept for replay to
  Zakura peers that connect later
  ([#1955](https://github.com/zakura-core/zakura/pull/1955)).
