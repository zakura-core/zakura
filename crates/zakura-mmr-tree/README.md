# zakura_mmr_tree

Zakura's Zcash chain history Merkle mountain range (MMR) implementation. It
supports versioned node metadata, serialization, hashing, and partially loaded
views for appending or truncating leaves. Zakura uses it to construct and validate
chain history roots; it does not provide standalone inclusion-proof APIs.

## Provenance

Imported from `zcash_history` 0.5.0 in
[`zcash/librustzcash`](https://github.com/zcash/librustzcash/tree/882ecd278050bb92365c9d1250c55f0dadc0f648/zcash_history),
commit `882ecd278050bb92365c9d1250c55f0dadc0f648`. The upstream MIT and Apache-2.0
licenses and contributor copyright notice are retained alongside this file.
Upstream developer examples are not included.

The tree algorithms, version selection primitives, and wire formats are retained.
The work integer uses Zakura's existing `uint` 0.10 dependency through this crate's
`U256`, replacing `primitive-types` and its older `uint` dependency. Test helpers
remain private to this crate's tests; `proptest` is a development dependency.
Index conversions reject views too large to represent with 32-bit entry links.

## Validation

The imported tests include independent ZIP 221 / ZIP 229 vectors for V1, V2, and
V3 trees. They compare exact serialized leaves, roots, peaks, and chain history
hashes across 16 leaves per version. Property tests cover metadata serialization,
append/truncate operations, tree lengths, and root structure.

```sh
cargo test -p zakura_mmr_tree
cargo test -p zakura-chain zcash_history
cargo test -p zakura-chain history_tree
```

## API

The public library retains upstream's `Entry`, `EntryKind`, `EntryLink`, `Error`,
`Tree`, `Version`, `V1`, `V2`, `V3`, `NodeData`, `NodeDataV2`, `NodeDataV3`,
`MAX_ENTRY_SIZE`, and `MAX_NODE_DATA_SIZE`. Their public fields, constructors,
serialization methods, hashing methods, error variants, tree operations, and
version trait methods retain their signatures apart from crate identity and the
new `U256` type used by `NodeData::subtree_total_work`. Indexed node handles
returned by tree methods retain their `node`, `data`, and `link` accessors.

`U256` exposes the unsigned 256-bit integer API generated by `uint::construct_uint!`.
Implementation modules and test generators are private. Crate-visible items are
entry fields, the three node-data combine helpers, error augmentation, peak
traversal, and test-vector data. These are internal to this crate.

Zakura's existing `zakura_chain::primitives::zcash_history` wrapper module remains.
Its re-exported versions, `Version` supertrait, `Tree` bounds, node-data conversion,
and append errors now use this crate's types. Its crate-visible `append_leaf_parts`
error type also changes, as does `HistoryTreeError::InnerError::inner`.
