## Changed

- Historical treestate derivation, added in
  [#703](https://github.com/zakura-core/zakura/pull/703), is no longer switched on by
  configuration. A verified-commitment-trees fast-synced node in archive mode derives whenever
  `state.historical_frontier_artifact` gives it a frontier grid to anchor on, and reports the
  same typed archive-mode error as before when no grid is configured. A derived treestate is
  served only if it reproduces the authenticated root the node already stores, so there was
  nothing for an operator to weigh, and startup no longer refuses to run over the flag and the
  grid disagreeing. Pruned mode is unchanged: it still cannot serve historical treestates,
  because replay reads block bodies it does not retain. `state.derive_historical_trees` and
  `state.max_historical_tree_replay_blocks` no longer exist, and a configuration file carrying
  either key no longer parses; the replay backstop is now a constant, because grid spacing, not
  that limit, is what decides the cost of a request
  ([#739](https://github.com/zakura-core/zakura/pull/739)).
