## Changed

- Gave Ironwood its own ZIP 218 per-block action limit of 330, instead of
  counting Ironwood actions against the Orchard limit. Both pools still draw on
  the one global shielded budget of 330, so a block cannot spend the per-pool
  capacity twice
  ([#1041](https://github.com/zakura-core/zakura/pull/1041)).

## Fixed

- Stopped banning peers that relay a mempool transaction which only a rule of
  the newly activated network upgrade rejects. For 40 blocks after any
  activation height, the ZIP 218 shielded limits and the previous upgrade's
  consensus branch ID no longer count as peer misbehavior, because an honest
  peer one block behind still admits such a transaction. Block verification is
  unchanged ([#1041](https://github.com/zakura-core/zakura/pull/1041)).
- Applied the ZIP 218 shielded limits during checkpoint verification. A network
  that activates NU7 below its highest checkpoint could otherwise commit an
  over-limit block to finalized state, because checkpoint-verified blocks skip
  semantic transaction checks
  ([#1041](https://github.com/zakura-core/zakura/pull/1041)).
