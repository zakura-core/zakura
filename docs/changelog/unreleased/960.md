## Changed

- The mempool still bans peers for stateless transaction failures, including
  invalid Halo2 proofs, invalid or malformed Groth16 proofs, invalid shielded proof sizes, and
  invalid transaction structure. These bans do not depend on tip freshness.
- For other previously scored transaction failures, the mempool ignores
  transactions from the peer's IP for 10 minutes. Each later cooldown doubles
  up to 2 hours and disconnects the peer without banning it. Failures already
  in flight during a cooldown do not count as another strike. Lock time and
  consensus branch ID failures start no cooldown. Block verification keeps
  its existing ban policy ([#960](https://github.com/zakura-core/zakura/pull/960)).

## Fixed

- Preserve transaction source attribution across mempool tip resets.
- Preserve active peer cooldowns when the history reaches capacity. Pause
  transactions from untracked IPs until a cooldown expires. Use an expiry index
  to evict expired entries without scanning the history.

- Fixed the mempool downloader so that a peer that answers a transaction
  request with a different transaction no longer leaks that request's download
  slot. The mempool now treats the response as a failed download
  ([#960](https://github.com/zakura-core/zakura/pull/960)).
