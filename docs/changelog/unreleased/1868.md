## Changed

- Limit admitted blocking state reads across service clones.
  Keep admission until cancelled jobs finish and reserve capacity for chain-tip reads
  ([#1868](https://github.com/zakura-core/zakura/pull/1868)).
- Bound full blocks decoded from disk and retain their admission through the last
  result handle. Report capacity refusal separately from missing data. Reserve
  separate result capacity for chain-tip publication.
- Share standalone disk-transaction admission across lookups and iterators.
  Retain admission through the last result handle. Report format diagnostics as
  incomplete when live read results exhaust capacity; periodic checks retry.
- Share header and serialized-block result admission across read services and
  retain it through the last result handle. Report capacity refusal separately
  from missing data. Header context reads inside a read job take no slot.
- Add `read_result_byte_limit` and `read_parser_byte_limit`, which separately bound
  decoded disk results and active parsers. A refusal returns a capacity error.
- Add `read_waiter_limit`, which bounds callers waiting for a blocking read worker.
- Refuse to start when read or verification limits cannot fund their workers, or
  when their sum exceeds the node allowance.
- Bound callers waiting for mempool outputs, and remove abandoned output and UTXO
  waiters while the chain tip stalls.
