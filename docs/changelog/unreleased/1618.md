This PR restructures the header-sync reactor's internals and fixes one stale
completion. Storage completions become a typed enum, locator reads gain exact
keys, and the reactor's scheduling records move into a `ReactorState` value.
Pure transitions now decide offers, pages, and repair suppliers. Retained
headers keep their capacity charged through prepare, apply, refusal, shutdown,
and cancellation.

One behavior changes on purpose: a storage completion settles a peer's work
only when its round incarnation and call match the work it completes. Before,
an earlier round's prepare or call with the same owner could settle a later
round. `an_earlier_rounds_prepare_cannot_settle_a_later_round_with_the_same_owner`
and `an_older_rounds_call_cannot_settle_a_later_round_with_the_same_owner` test
the gate.

The version 9 table now declares header sync's per-connection memory share,
`HEADER_SYNC_BUDGET`, and `v9::budget` selects it by network. Nothing reads it
yet: the node composition wires it into the receive window later.

One new counter, `sync.header.port.unknown_settlement`, counts a storage call
that settles twice or never started. Wire formats, configuration, and traces do
not change, so it has no operator- or crate-consumer-visible effect.
