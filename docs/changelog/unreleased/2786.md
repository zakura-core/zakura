## Changed

- A v2 node now uses its Zakura bootstrap peers only to find its first peers. Only the bootstrap dialer dials them, at most two at a time, while the node has outbound peers on fewer than two other hosts. Besides a bootstrap peer's configured address, it dials the addresses the peer's signed record advertises, so a bootstrap peer that moved stays reachable. Once outbound peers on four other hosts have stayed connected for a minute, it closes the connections it opened to them. A node whose connection cap leaves few slots for its own dials waits for fewer hosts, but at least two. A connection a bootstrap peer opened, a pinned peer's, or a legacy-to-v2 upgrade's stays. The bootstrap peers' inbound slots no longer fill once the v2 network outgrows them. A node whose own ID is among its bootstrap peers, such as a default seed or a node in a fleet that lists all its nodes, still keeps every other bootstrap peer connected, so those nodes stay a full mesh. Any other node that finds no other peers keeps two bootstrap peers connected instead of all ([#2786](https://github.com/zakura-core/zakura/pull/2786)).
