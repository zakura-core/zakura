## Security

- Prevent a peer's modified block body from permanently excluding a valid header
  and its descendants from native block sync. Duplicate padding can preserve the
  transaction Merkle root (CVE-2012-2459) and NU5 authorization changes can
  preserve transaction IDs, so a body failure now counts as permanent header
  invalidity only when the header's Merkle root and NU5 authorization commitment
  bind the delivered body. Other failures are attributed to the supplier, which
  native sync now defers before refetching the body. A header whose deliveries
  never bind now raises the persistent body-unavailable alarm once every
  eligible supplier has been tried, instead of being retried without an
  operator-visible signal. This prevents new incorrect exclusions but does not
  clear previously stored ones
  ([#999](https://github.com/zakura-core/zakura/pull/999)).
