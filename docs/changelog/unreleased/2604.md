## Changed

- A slow or stalled v2 peer now loses only the affected service session. The node
  resets that session's streams and keeps the connection, so header sync, block sync and
  discovery on the same peer keep running. A second stall on the same connection closes
  it, and a stall never counts as a peer fault
  ([#2604](https://github.com/zakura-core/zakura/pull/2604)).
- Inbound v2 handshakes now share a node-wide rate of 24 starts a second for each source
  validation state. The 10-second handshake deadline now starts when the connection is
  accepted, and a registered connection keeps its per-address handshake charge
  ([#2604](https://github.com/zakura-core/zakura/pull/2604)).
- A rate-limited discovery stream now waits for its next token instead of only tracing,
  and header sync meters peer `Status` messages and the locator walks of new
  subscriptions ([#2604](https://github.com/zakura-core/zakura/pull/2604)).

## Fixed

- Fixed a peer's answer from another chain after a reorg closing its whole v2
  connection; the node now resets only the block-sync session and requeues the heights
  ([#2604](https://github.com/zakura-core/zakura/pull/2604)).
- Fixed the discovery dial history growing without a cap; it now keeps at most 32,768
  entries ([#2604](https://github.com/zakura-core/zakura/pull/2604)).
- Fixed a replaced v2 connection releasing its per-IP slot while the old connection
  still ran ([#2604](https://github.com/zakura-core/zakura/pull/2604)).

## Security

- Header sync now stops starting Equihash checks after the first invalid header and checks
  a page's credit before hashing it, and discovery checks a `Hello`'s network and chain
  before its signature ([#2604](https://github.com/zakura-core/zakura/pull/2604)).
