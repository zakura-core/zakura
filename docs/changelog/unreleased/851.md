## Added

- Added ZIP 218 "25-second Block Target Spacing" behind the off-by-default
  `nu7` build feature. From NU7 activation onwards, the rules apply a
  25-second block target spacing, a 102-block difficulty averaging window, a
  block subsidy divided by the spacing ratio, and per-block shielded action
  limits. The rules stay dormant until NU7 has an activation height on the
  configured network, so a build with this feature follows today's consensus
  on Mainnet and Testnet
  ([#851](https://github.com/zakura-core/zakura/pull/851)).
- Counted Ironwood actions against the ZIP 218 Orchard action limit and in the
  global shielded budget. This goes beyond ZIP 218, which names only Orchard
  actions, because NU6.3 moves new Orchard-protocol value to the Ironwood pool
  ([#851](https://github.com/zakura-core/zakura/pull/851)).
- Rejected mempool transactions whose own shielded actions exceed a ZIP 218
  per-block limit, with misbehavior score 100, because no block can include
  them. ZIP 218 does not specify this rejection
  ([#851](https://github.com/zakura-core/zakura/pull/851)).
- Let a node switch between a `nu7` build and a default build on the same
  database. A `nu7` build extends the stored difficulty context at startup,
  and a default build trims it back
  ([#851](https://github.com/zakura-core/zakura/pull/851)).
