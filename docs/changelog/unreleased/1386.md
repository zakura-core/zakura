## Changed

- The state database stays in `state/v30/{network}` for every later format
  change. A format change that older Zakura versions cannot read now raises the
  database's minimum reader version, recorded in a new `state_manifest` column
  family, instead of moving the database to a new directory
  ([#1386](https://github.com/zakura-core/zakura/pull/1386)).
- An older Zakura version now refuses to open a database whose minimum reader
  version is newer than its own format, and names the version it needs.
  Previously it rewrote the database version and continued. An older version
  that the database still allows leaves the newer version on disk
  ([#1386](https://github.com/zakura-core/zakura/pull/1386)).
- Startup now refuses to move a previous-major database that another process
  has open, such as an older node that is still running. It also fails with a
  hint, instead of starting an empty database, when the move fails or the
  previous database resolves outside the cache directory
  ([#1386](https://github.com/zakura-core/zakura/pull/1386)).
- Old database cleanup now deletes the running network's database from every
  older major directory once the current database exists, and keeps a database
  that another process has open. Other networks keep their older databases
  until they start
  ([#1386](https://github.com/zakura-core/zakura/pull/1386)).

## Removed

- Removed the format upgrades from state database formats older than 28.0.0.
  No Zakura release wrote such a database. Startup refuses one and asks the
  operator to resync it
  ([#1386](https://github.com/zakura-core/zakura/pull/1386)).
- Removed support for Zebra version files that omit the major version. Startup
  also no longer guesses the format of a database without a version file, and
  refuses one that holds blocks
  ([#1386](https://github.com/zakura-core/zakura/pull/1386)).
- Removed `zakura_state::restorable_db_versions`, `ZakuraDb::major_version`,
  and `DiskDb::major_version`
  ([#1386](https://github.com/zakura-core/zakura/pull/1386)).

## Fixed

- Read-only state tools, such as `zakurad tip-height`, and the panic report now
  find a previous-major database that the node has not moved yet
  ([#1386](https://github.com/zakura-core/zakura/pull/1386)).
