## Changed

- With `[network.block_download_score_and_hedge] enabled` on, legacy block
  download scoring now predicts arrival time from each peer's 10-minute sliding
  minimum heartbeat RTT and 10-minute incoming block transfer rate instead of
  an exponentially decayed combined average. Unmeasured announcers inherit the
  live ready-fleet median RTT and transfer rate for primary selection, while
  speculative `predicted` second requests still require a peer's own measured
  RTT and `stalled` rescues may fall back to an unmeasured announcer. Second
  requests are now scheduled inside the peer set after waiting primary requests
  so hedges do not take ready peers from primary downloads. The
  `legacy_peer_request` trace fields are unchanged, and `delivery_score.jsonl`
  is no longer written
  ([#2693](https://github.com/zakura-core/zakura/pull/2693)).
