## Security

- Reject duplicate-padded block deliveries without permanently excluding a valid
  header. Reuse early authorization checks to distinguish padding from duplicates
  that the header commits to. Preserve supplier attribution while checkpoint
  parents remain uncommitted and score duplicate-transaction deliveries.
- Defer native suppliers after payload mismatches, including requested deliveries
  with the wrong header, and preserve exclusions across compatible authority
  refreshes. Let eligible alternatives serve the missing block, refill capacity
  released by detached completions, and retry body-unavailable actions after
  local backpressure. Persist retry age, attempts, and exact supplier history
  across restarts; expose unavailable intermediate blocks on the selected chain
  and retain retry evidence across stale or temporarily unavailable state writes.
  Existing false tombstones still require separate recovery
  ([#1039](https://github.com/zakura-core/zakura/pull/1039)).
