## Changed

- The Mainnet historical frontier grid is now distributed as an exact-pinned crates.io
  package built from `assets/zakura-assets/` instead of being committed to this repository.
  At ~4.7 MB regenerated on every weekly release-state refresh, committing it would add that
  much to the repository's history each time; the payload is generated at publish time and
  never enters git. The release-state workflow publishes the grid before opening the pull
  request that pins it, because cargo can only resolve a version that already exists. The
  version is `0.<last_checkpoint>.<revision>`, so the pin states which checkpoint the payload
  covers, and `scripts/check-release-state.sh` holds that against the provenance manifest
  without cargo while `embedded_mainnet_final_frontiers_parse` hashes the bytes the dependency
  supplies and holds them against the manifest's recorded digest. The release-state import now
  proves each grid extends the previously published one rather than a committed file. Nothing
  about node behavior changes: the grid still carries no trust weight, and every entry is
  checked against the node's own authenticated root before it anchors anything
  ([#763](https://github.com/zakura-core/zakura/pull/763)).
