## Added

- Added `mining.submit_acknowledgement`. Operators can select strict
  `"committed"` responses or return after active writer admission with
  `"queued"`.
- Added `network.block_relay` with `"contextual"` as the default. A node can relay
  a contextually valid child of its selected tip while storage and tip
  publication continue. Operators can select `"committed"` for strict
  commit-before-relay behavior. Nodes that are still syncing use the strict path
  even when `"contextual"` is configured.

## Changed

- Reduced block propagation latency by authorizing inventory after contextual
  validation and staged best-chain selection but before storage. Both P2P stacks
  still use inventory and pull; Zakura does not push full blocks.
- Applied the selected block relay boundary to both P2P stacks. Native Zakura
  block sync owns Zakura block bodies, and Zakura gossip forwards a block only
  after state authorizes relay.
- Added independent block lifecycle milestones for relay authorization, writer
  admission, contextual validity, storage application, in-memory publication,
  and terminal commit.
- Added lifecycle, contextual commit, integrated storage, publication, and
  relay latency metrics for the profiling pass.
- Bounded pre-commit block bodies and recent relay records by count and age.
- Made storage-uncertain header transition failures stop the state writer and
  mark the state service unready.
- Preserved the precomputed authorizing-data root through contextual validation
  so the state service does not recompute it
  ([#773](https://github.com/zakura-core/zakura/pull/773)).
