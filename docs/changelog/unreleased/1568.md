## Security

- Fixed a checkpoint sync stall caused by a peer serving a checkpoint block
  with altered authorizing data. Inside the last 1,000 checkpoint heights, a
  sync restart after the rejection could stop the node from downloading the
  block again until a process restart. Elsewhere, the rejected block's
  descendants waited up to 8 minutes for a response. The node now downloads
  the block again right away. At ZIP 234 heights, the verifier also releases
  descendants waiting for parent information after a body rejection.
  Native block sync gives up on a commit that
  does not finish within 8 minutes
  ([#1568](https://github.com/zakura-core/zakura/pull/1568)).
