# Zakura published assets

Zakura's reviewed Mainnet historical frontier grid, distributed as a crates.io package so the
bytes are embedded at compile time without being committed to a git repository.

The payload in `src/` is generated by `scripts/pack-assets-crate.py` in the
[Zakura repository](https://github.com/zakura-core/zakura) from one immutable release-state
bundle, and is not present in a checkout. Build and publish this package only through that
script.

## The grid carries no trust weight

Every entry a node takes from this grid is checked against the authenticated note-commitment
root it already holds for that height before the entry anchors anything, and a failed check is
skipped rather than fatal. Corrupt or hostile bytes produce a node that declines to answer, not
one that answers wrongly.

## Verifying a published version

```sh
V=<version>
N=<crate name>
curl -sLO "https://static.crates.io/crates/$N/$N-$V.crate"
tar xzf "$N-$V.crate"
sha256sum "$N-$V/src/mainnet-frontier-grid.bin"
cat "$N-$V/.cargo_vcs_info.json"
```

`.cargo_vcs_info.json` names the Zakura commit this package was built from. It is marked dirty
because the payload is generated and gitignored, so the publish passes `--allow-dirty`.

The digest must equal `frontier_grid_sha256` in Zakura's
`crates/zakura-state/src/service/finalized_state/vct/mainnet-vct-manifest.json` at the commit
that pins this version. See `docs/design/historical-treestate-serving.md` for the full
verification procedure, including independent regeneration from an archive node.
