## Fixed

- Zakura block sync now schedules a body without a known size hint with a moving average of recently accepted body sizes instead of the 2 MB worst case. Small blocks from peers that send no size hints can therefore use the available download capacity. Memory admission still charges these bodies at the worst case. Forward resets immediately retire stale reservations and preserve the reset estimate
  ([#1025](https://github.com/zakura-core/zakura/pull/1025)).

- Inbound block serving applies its configured serialized-byte budget while reading state, before accumulating the response bodies.

- Late matching bodies settle the current active request atomically after reassignment, and completed or displaced reservations no longer charge peer timeouts. Committed heights cannot receive floor-rescue priority.

- Pending size-hint updates wake waiting peers, returned requests use current same-epoch hints, and late deliveries refund reliability only once for an exact request that the delivering peer previously timed out.
