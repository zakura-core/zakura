This PR removes duplicate block-sync control decoding, shares ending completion, and separates
Status cadence deferral from queue pressure in diagnostics. It changes no wire bytes or peer fault
policy, because production already decoded peer controls with the strict codec.

For crate consumers, the public `BlockSyncMessage` encoder and decoder now reject out-of-range Status
limits, a servable range whose low is above its high, and a `GetBlocks` range past the last height.
They no longer clamp or accept these values. `BlockSyncWireError` replaces three count and height
variants with `Wire`. The pending `zakura-network` major version covers this change.

A `status_refresh_interval` above the protocol's 30 s Status cadence now paces every Status on a
connection, not only refreshes.
