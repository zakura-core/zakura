## Added

- Added `state.derive_historical_trees`, which lets a verified-commitment-trees fast-synced
  node answer `z_gettreestate` and the `getblock`/`getblockheader` tree sizes for the
  height band where it stored no per-height note commitment tree. The node replays
  retained block bodies forward from the nearest frontier it already holds and serves the
  result only if it reproduces the authenticated root it already stores, so the treestate
  is verified rather than trusted. Off by default, and unchanged behavior when off: the
  same typed archive-mode error, never a null treestate. Enabling derivation requires
  `state.historical_frontier_artifact`; startup fails closed if the flag is on and no
  grid is configured, so a cold request cannot replay the entire absent band.
  `state.max_historical_tree_replay_blocks` is then a backstop on what one request may
  cost from the nearest grid entry. Pruned mode still returns the typed archive-mode
  error, even with the flag on, because derivation needs retained block bodies
  ([#703](https://github.com/zakura-core/zakura/pull/703)).

- Added generation for that frontier grid. It ships as part of the Mainnet release-state
  export rather than as its own subcommand; see
  [#735](https://github.com/zakura-core/zakura/pull/735)
  ([#703](https://github.com/zakura-core/zakura/pull/703)).
