## Security

- Bound native `GetBlocks` serving work per peer and across the node, while
  retaining one response producer per authenticated peer across reconnects until
  state work and transport writes finish. Delay locally saturated requests without penalizing the
  requesting peer or adding serving byte budgets. Keep reading responses while
  serving waits for capacity, with a bounded queue of waiting requests, so peers
  serving each other can both progress. Close only the block-sync stream if that
  queue overflows. Retain response terminators through temporary output queue
  pressure.
  Reject response byte limits below the maximum block size so available blocks
  can be served. Reject GetBlocks ranges extending past the maximum supported
  height on both send and receive. Reject oversized GetBlocks frames from their
  headers before allocating or reading their payloads. Report requests before
  Status as `get_blocks_before_status`
  instead of `get_blocks_spam`
  ([#892](https://github.com/zakura-core/zakura/pull/892)).
