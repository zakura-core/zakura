## Changed

- **Breaking for v2 P2P:** the v2 handshake moves to NIST security category 5.
  The hybrid key exchange is now X25519MLKEM1024 and handshakes are signed
  with a composite of Ed25519 and ML-DSA-87. Every node's ID changes again
  and the v2 protocol moves to version 5 (ALPN `p2p-v2/5`) with no overlap
  with version 4, so nodes on v1.9.0-rc2 reach this release only over the
  legacy protocol. Key files don't change, but entries in
  `zakura.bootstrap_peers` and pinned `network.unconditional_peers` name a
  peer by its node ID, which a node prints for itself at startup, so existing
  entries need the peer's new ID. A new v2 connection takes one more round
  trip to complete, and each handshake moves about 21 KB in place of 12 KB
  ([#2723](https://github.com/zakura-core/zakura/pull/2723)).
- `zakura-quic` replaces `ML_DSA_44_KEY_TAG`, `ML_DSA_44_KEY_BYTES` and
  `ML_DSA_44_SIGNATURE_BYTES` with `ML_DSA_87_KEY_TAG`, `ML_DSA_87_KEY_BYTES`
  and `ML_DSA_87_SIGNATURE_BYTES`, and `COMPOSITE_SIGNATURE_BYTES` grows to
  4,691 ([#2723](https://github.com/zakura-core/zakura/pull/2723)).
