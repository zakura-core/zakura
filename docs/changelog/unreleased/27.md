## Fixed

- Mempool activation and crawling now require both near-tip sync throughput and
  a local-clock estimate that the chain tip is within 100 blocks of the network
  tip. A peer-starved syncer no longer makes a node far behind the network tip
  start its mempool and ban honest peers for transactions it cannot validate.
  An active mempool now disables when the estimate exceeds the 1000-block
  rollback window, and the mempool only scores transaction verification
  failures against peers while the estimate is within 100 blocks
  ([#27](https://github.com/zakura-core/zakura/pull/27)).
