## Added

- Added ZIP 218 "25-second Block Target Spacing" rules at NU7. From the
  configured NU7 activation height onwards, the rules apply a 25-second block
  target spacing, a 102-block difficulty averaging window, a block subsidy
  divided by the spacing ratio, and per-block shielded action limits. Networks
  without an NU7 activation height follow today's consensus
  ([#851](https://github.com/zakura-core/zakura/pull/851)).
- Counted Ironwood actions against the ZIP 218 Orchard action limit and in the
  global shielded budget. This goes beyond ZIP 218, which names only Orchard
  actions, because NU6.3 moves new Orchard-protocol value to the Ironwood pool
  ([#851](https://github.com/zakura-core/zakura/pull/851)).
- Rejected mempool transactions whose own shielded actions exceed a ZIP 218
  per-block limit, with misbehavior score 100, because no block can include
  them. ZIP 218 does not specify this rejection
  ([#851](https://github.com/zakura-core/zakura/pull/851)).
- Retained ZIP 218's maximum difficulty context in every build. Startup extends
  older, narrower contexts before validation
  ([#851](https://github.com/zakura-core/zakura/pull/851)).

## Changed

- Scaled non-consensus timing to the target spacing at each height, so it
  follows the 25-second spacing after NU7: the Testnet `getblocktemplate`
  minimum-difficulty heuristic, the `getnetworksolps` default window, the
  legacy syncer lookahead (3 times larger, as ZIP 218 recommends), the
  end-of-support halt and warning heights, the `getdeprecationinfo` estimate,
  and the sync stall warning. Networks without an NU7 activation height behave
  as before ([#851](https://github.com/zakura-core/zakura/pull/851)).

## Fixed

- Fixed the Testnet `getblocktemplate` heuristic to read the minimum-difficulty
  gap at the candidate block's height, as the consensus rule does
  ([#851](https://github.com/zakura-core/zakura/pull/851)).
