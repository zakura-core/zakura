## Changed

- On a chain configured for post-quantum transparent outputs, threshold spends use
  `OP_CHECKSIGADD` instead of `OP_CHECKMULTISIG`, which is invalid anywhere in a
  post-quantum script. Each signature check with a non-empty signature costs one
  signature's size of the input, and a signature that fails makes the spend invalid.
  A post-quantum input's signature operations, for block limits and the relay limit,
  count the smaller of the script's checking opcodes and the checks its input pays for
  ([#2807](https://github.com/zakura-core/zakura/pull/2807)).
