## Added

- Added `state.derive_historical_trees`, which rebuilds historical note commitment trees
  on demand so `z_gettreestate`, `getblock` and `getblockheader` work below the checkpoint
  handoff on a fast-synced archive node. Each rebuilt tree is served only if it reproduces
  the authenticated root the node already stores, and results are memoized so a wallet
  scanning forward pays for one batch of replay per request. Bounded by
  `state.max_historical_tree_replay_blocks`, and disabled by default
  ([#529](https://github.com/zakura-core/zakura/pull/529)).
- Added the `audit-historical-treestates` subcommand, which reports whether a state
  database can serve historical treestates and can walk the affected range to check and
  time every rebuilt tree
  ([#529](https://github.com/zakura-core/zakura/pull/529)).

## Fixed

- Fixed `z_gettreestate` returning a JSON `null` treestate, and `z_getsubtreesbyindex`
  returning an empty list, for heights a fast-synced node has no data for. Clients
  following the lightwalletd contract read an absent treestate as the _empty_ tree, so a
  wallet could derive a birthday anchor asserting an empty commitment tree deep in the
  chain with no error raised. Both now return a typed archive-mode error
  ([#529](https://github.com/zakura-core/zakura/pull/529)).
- Fixed read-only state opens failing against databases written by an older version, which
  made read-only tooling unable to inspect them at all. Opening read-only no longer
  requires column families the database does not have
  ([#529](https://github.com/zakura-core/zakura/pull/529)).
