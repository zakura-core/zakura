## Added

- `network.unconditional_peers` now also takes a DNS name with a port, such as
  `"peer.example.com:8233"`. Zakura looks the name up before each dial, and
  never while that peer is connected, so it follows a peer that comes back at a
  new address without a config change or a restart. It dials the first address
  in the answer that it can dial, so each peer needs a name of its own. That
  address is treated like a listed address until the name resolves to another
  one. When a lookup fails, Zakura dials the last address again. A name without
  a port fails config load
  ([#2478](https://github.com/zakura-core/zakura/pull/2478)).
